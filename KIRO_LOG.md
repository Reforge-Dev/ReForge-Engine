## Fri Nov 27 (Muhammad, Kiro IDE session)

The engine code (v0.1.0) was written outside Kiro. This session used Kiro to reconcile the spec with it, add property tests, hooks and steering.

- **Specs.** Rewrote `.kiro/specs/engine-core/requirements.md` against the shipped code (status note, center-based x/y, new R15-R20 for rules, registry, timers/targets, widgets, tables, game events). Wrote `design.md` from the code with 3 mermaid diagrams, a correctness-properties table and 12 "known deviations". Wrote `tasks.md` with shipped work marked `[x]` and the commit that implemented it. Reading the code for `design.md` found two mismatches with the team brief: draw order is layer/y/id, not array order, and the editor's Bring front/Send back depend on array order (task T16, open).
- **Property tests (fast-check).** Passed first run: P1 determinism (100 runs x up to 90 ticks, plus restart reproduces run 1), P4/P5 collision (1000 and 300 runs), P6 validator mutations of `examples/hello/game.json` (1000 runs), P7 manifest and docs freshness. **P2 failed and found a real bug**: shrunk counterexample `add{type:"a", id:"b-1"}`, `clear()`, `add{type:"b"}`. The last add generated `b-1`, an id already issued to a removed entity (violates R4.2). The existing 75 unit tests did not cover it. Fixed in `cd21853` by recording issued ids (cleared on restart).
- **Hooks (3, `.kiro/hooks/*.json`, trigger `PostFileSave` with a path matcher, command `node engine/scripts/hook-run.mjs <gen|ts|game>`).** Created with the createHook tool. They activate on the next session start, so I have NOT seen the IDE fire them yet. What I verified: the matcher regexes against 10 sample paths, and each script run by hand with a fake hook payload, logged to `engine/dist/hooks.log` (PASS for valid input, FAIL with exit 1 for stale `docs/behaviors.md` and for a broken `game.json`). To capture the real proof: restart the session, save `engine/src/behaviors/actions.ts`, `engine/src/core/world.ts` and `examples/hello/game.json`, then read `engine/dist/hooks.log`.
- **Steering.** Rewrote `structure.md`, `tech.md` and `behavior-authoring.md` for the real layout (`$` references, `not`, targets, "one registry entry"). The `fileMatch` doc was injected into my context the moment I edited files under `engine/src/behaviors/`, and its old text was stale (it described `behaviors/<kind>/<name>.ts` and pure-function actions, which do not exist). That is the clearest example so far of steering shaping output, for better or worse.
- **Surprises.** (1) `pnpm -r lint` runs nothing; lint is a root script. (2) `PostFileSave` hooks cannot block a save and their stdout is not forwarded, so "fail" means a non-zero exit plus a log line. (3) My first `gen` hook script passed when it should have failed (`git status --porcelain` output was trimmed, hiding the leading space); I only caught it by testing the failing case on purpose. (4) My own commit helper kept going after a failed lint step on a CRLF checkout; I re-ran the gate and fixed it after the fact. (5) The shipped renderer contradicts the "array order" decision.
